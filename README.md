# Pocket Photogrammetry Scan

ポケットフォトグラメトリースキャン（PocketScan）

Version 0.2.0

スマホのブラウザで写真を取り込み、端末内で3Dを再構成するPWAの実験版です。写真はサーバーに送信しません。AndroidのChrome最新版を主な利用対象としています。iOS実機は未検証です。

## ローカルで起動

Python 3がある環境で、リポジトリのルートから次を実行します。

```bash
python3 -m http.server 8080 --directory dist
```

PCのブラウザで [localhost:8080](http://localhost:8080) を開きます。スマホで利用する場合は `dist/` をHTTPS対応の静的ホスティングで配信してください。HTMLファイルを直接開く方法には対応していません。

本体・3Dエンジン・依存ライブラリは同梱済みです。アプリの起動にnpmビルドやAPIキーは必要ありません。

## 使い方

1. HTTPSのアプリを開き、「写真を選ぶ」で同じ被写体の写真を追加します。1プロジェクト最大1,000枚です。
2. 「設定」で軽量・標準・詳細を選びます。まず20〜60枚、軽量または標準で試してください。
3. 撮影順を確認して「3Dを作成」。処理中は画面を開いたままにします。
4. 「中断して保存」で途中保存します。ブラウザが終了しても、直近のチェックポイントまたは保存済み特徴から再開できます。
5. 「3Dビュー」で回転・拡大縮小し、色付き点群または部分メッシュをPLY、GLB、OBJで書き出します。
6. オフライン準備済みの表示を確認すると、以後は通信なしでも処理できます。ホーム画面への追加にも対応しています。

被写体を固定し、同じレンズ・ズーム・向きで、隣の写真と7〜8割重なるよう周囲を移動して撮影します。回転だけで位置を変えない撮影、反射・透明・無地・動く被写体は適しません。

## 実装済み

- 写真の逐次縮小・JPEG保存、SHA-256による重複検出、24枚ずつのサムネイル表示。
- IndexedDBのトランザクション内で1,000枚の上限を検査。複数タブの書き込みはWeb Locksで排他。
- 原本を変更せず、長辺1,600px以下の処理用画像とサムネイルを保存。
- EXIFの撮影日時・35mm換算焦点距離を読む。情報がない場合の焦点距離は設定可能。
- OpenCV WebAssemblyのORB特徴・Hammingマッチング、正規化8点法とRANSAC、Essential行列からの姿勢復元。
- 8枚以下では基準ペアを全組確認し、ORBで基準を作れない場合にAKAZEで一度再解析。3Dの幾何検証は維持。
- PnP RANSACによる逐次カメラ登録、正の奥行き・視差・再投影誤差による三角測量の検証。
- 基準2カメラを固定した姿勢LMと多視点光線交差の交互調整。
- 近隣視点間のピラミッドLK、往復追跡、パッチ相関、再投影誤差を検査する半密な点群と部分メッシュ。
- カメラ登録5枚ごとのチェックポイント、各表面ペアの保存、処理の中断・再開。
- Three.jsによる操作可能な3D表示、PLY（バイナリ）・OBJ・GLB 2.0書き出し。
- 全実行コードとWASMの同一オリジン配信・Service Worker保存。APIキー不要。

## 制限

- **1,000枚のスマホ実機での完走は未検証**です。登録上限1,000枚のストレージ検証と、12枚の合成透視画像による画素入力からの再構成を検証しました。所要時間・熱・電池・実機メモリの保証はありません。
- 商用品相当の高密度な全面・閉曲面のメッシュを生成するエンジンではありません。模様を追跡できた部分だけに面を作り、穴・部分欠損・重複面が残ります。
- 結果の縮尺は任意です。実寸測定、精密部品の測定用途には使えません。
- 一括の大規模Bundle Adjustment、Loop Closure、レンズ歪み補正、Poisson面生成、UVテクスチャ貼り付けは未対応です。大きな一周の撮影や長いシーケンスはドリフトが生じる場合があります。
- 基本は順序付きシーケンスです。未登録写真を再試行しますが、バラバラの写真集合・独立した複数の撮影領域の統合は保証しません。
- 詳細モードでも写真の長辺は最大1,600pxです。上限は軽量/標準/詳細で疎な点群7万/12万/16万点、半密な点群24万/45万/65万点。上限到達後も写真の位置推定を続け、表面点は追加しません。
- カメラ登録に失敗した写真は結果から除外し、その名前を表示します。正しく対応付けできない場合にはエラーで停止し、代わりのモデルは生成しません。
- 半密な再構成は画像の向き・寸法が同じ近隣ペアを対象とします。
- 写真1枚の上限80MB。JPEG/PNG/WebPを対象とし、HEIC/HEIFはブラウザのデコーダー次第です。
- バックグラウンドや画面ロック中の継続処理は保証しません。ブラウザの保存データ削除でプロジェクトも消えるため、必要なモデルは書き出してください。
- オフライン利用には最初に全アセット（約13MB）の読み込みが必要です。

## 構成

`dist/` がビルド不要の静的アプリです。写真と計算結果はサーバーに保存せず、端末・ブラウザごとに独立しています。複数端末の同期やAPKは含みません。ブラウザ表示の動作・実機カメラ・PWAインストールは未検証です。

開発時は任意の静的サーバーで `dist/` を配信します。スマホからはHTTPSが必要です。PCのlocalhostはセキュアコンテキストとして扱われます。依存実行コードを同梱しているため、通常利用にnpmのインストールやビルドは不要です。

## 検証

```bash
node tests/geometry.mjs
python3 tests/generate-fixtures.py /tmp/pocketscan-fixtures
node tests/reconstruction.mjs /tmp/pocketscan-fixtures
node tests/three-photos.mjs /tmp/pocketscan-fixtures
node tests/service-worker.mjs
# fake-indexeddb 6.2.4を展開したpackageへのパス
node tests/storage.mjs /path/to/fake-indexeddb/package
```

Pythonのフィクスチャ生成にはNumPyとPillowが必要です。テスト用画像は既知のカメラから模様付き立体を透視投影して生成します。点の位置を直接エンジンへ渡す代用品ではありません。

画素入力テストの結果：12/12カメラ、4,969点、再投影誤差中央値0.367px。2視点の半密な再構成で2,055点・926三角形。GLBのKhronos形式検証でエラー・警告とも0。IndexedDB互換テストでは1,000枚保存、上限直前の同時追加拒否、重複拒否、削除後の再追加を確認。これは合成画像の結果であり、実際の写真の精度保証やスマホの速度評価ではありません。

## 0.2.0 の修正

- 失敗・ユーザーによる中断・ブラウザ終了などによる未完了を別々に保存・表示。失敗時は操作ボタンの近くに停止理由と再試行を表示します。
- 基準ペアの進捗を実際の確認組数で計算。3枚では全3組を確認します。
- 3枚の合成透視画像で通常のORB経路と代替のAKAZE経路を検証。近い視点のAKAZE結果は873点、離れた視点は320点、どちらも3枚を登録しました。
- 模様のない画像・無関係な画像・同一視点の画像では、それぞれ理由を示して終了し、代わりの形状を生成しないことを検証しました。
- 旧版からは同じブラウザで `/update.html` を開いて更新できます。写真やプロジェクトの保存領域は削除しません。別タブで取り込み・再構成中の場合は更新を待つよう案内します。
